# The RAG Test

A blunter cut: **replace your entire "memory layer" with a good-enough search engine.** If system behavior shows no material difference, it was never memory — only retrieval.

## Why

RAG as a tool is beyond reproach. RAG as a *memory architecture* is a category error: it compresses the entire life of memory into the moment of retrieval, shaped by the query. A memory layer is supposed to do things retrieval cannot.

## Protocol

1. **Pre-declare** — *before* the swap — a workload and an outcome criterion. This step is not optional: without a pre-declared criterion, "no material difference" is unfalsifiable.
2. **Swap.** Replace the memory layer with a good-enough search engine over the same raw content.
3. **Measure** on the pre-declared criterion.
4. **Judge** by that criterion only.

> Fix, in advance, a workload and an outcome criterion; if behavior shows no material difference on that pre-declared criterion, the layer was, **by that measure**, retrieval only — not memory.

## What "memory, not retrieval" requires

For memory to be *memory*, there must be evidence **beyond the query**:

- **Salience that grows while unretrieved** — structure forms without anyone asking.
- **Metabolism that happens while unobserved** — items retire on lifecycle, not on access.
- **Memories that shape behavior without being asked about** — influence that does not pass through a lookup.

## Honest boundary

The RAG Test is only as valid as its declared workload and criterion. A vague criterion will produce a vague verdict. State both explicitly, then let the test run.
